1. Polynomials as Singly Linked Lists

In computer science, a polynomial in one variable can be represented efficiently as a singly linked list. Unlike an array of coefficients (which would waste memory for sparse polynomials like x^1000 + 1), a linked list allocates a node only for non-zero terms.

P(x) = 5x^4 + 3x^2 + 2x + 7

head -> [ 5 | 4 | next ] -> [ 3 | 2 | next ] -> [ 2 | 1 | next ] -> [ 7 | 0 | next ] -> NULL
          coef  exp           coef  exp

Node Anatomy

Each node in the list stores three fields:

  • Coefficient (coef): The numerical multiplier (integer from -999 to 999).
  • Exponent (exp): The power of x (whole number from 0 to 99).
  • Next pointer (next): A reference pointing to the subsequent node, terminating at NULL.

Canonical Form

A polynomial linked list is in canonical form when:

  1. Terms are arranged in strictly descending exponent order.
  2. No exponent appears more than once.
  3. No node contains a coefficient of 0.
  4. The zero polynomial is represented by an empty list (head is NULL).

2. Two-Pointer Traversal Try in Visualizer →

Idea: Inspired by the merge step of Merge Sort. Pointers p and q traverse both sorted lists simultaneously. At each step, compare the exponents of the current nodes:

  • If p.exp > q.exp: copy term from P to R and advance p.
  • If q.exp > p.exp: copy term from Q to R and advance q.
  • If p.exp == q.exp: sum the coefficients. If non-zero, append to R. Advance both p and q. If the sum is zero, drop the term.
  • When one list finishes, copy all remaining terms of the other list directly to R.
1  p = P.head; q = Q.head; R = empty
2  while p != NULL and q != NULL:
3    if p.exp == q.exp:
4      sum = p.coef + q.coef
5      if sum != 0: append(R, sum, p.exp)
6      p = p.next; q = q.next
7    else if p.exp > q.exp:
8      append(R, p.coef, p.exp); p = p.next
9    else:
10     append(R, q.coef, q.exp); q = q.next
11 copy every remaining node of P or Q into R
12 return R

Complexity: Time is O(m + n), where m and n are the term counts of P and Q, because each comparison advances at least one pointer. Extra space is O(1) apart from the output list.

3. Nested-Loop Traversal Try in Visualizer →

Idea: Works without requiring either polynomial to be sorted! An outer pointer p iterates over every term in P. For each term, an inner pointer q scans through Q searching for a matching exponent.

  • Matched terms are summed and marked with a visited flag so they aren't added twice.
  • Unmatched terms in P are appended directly.
  • In Phase 2, all remaining unvisited nodes of Q are copied to R.
  • In Phase 3, the resulting list R is sorted into descending exponent order.
1  R = empty; mark every node of Q unvisited
2  for each node p in P:
3    found = false
4    for each unvisited node q in Q:
5      if p.exp == q.exp:
6        sum = p.coef + q.coef
7        if sum != 0: append(R, sum, p.exp)
8        mark q visited; found = true; break
9    if not found: append(R, p.coef, p.exp)
10 for each unvisited node q in Q: append(R, q.coef, q.exp)
11 sort R by exponent, descending
12 return R

Complexity: Scan phase takes O(m × n) time. Sorting k terms adds up to O(k^2) in worst case. Space is O(n) for visited flags plus output.

4. Insertion-Based Approach Try in Visualizer →

Idea: Models updating an existing polynomial. First, copy P into R. Then, take each term of Q, locate its correct sorted position in R using cursor c and trailing pointer prev, and either merge with an existing node or link in a new node.

  • If exponent matches: add coefficients. If coefficient cancels to 0, unlink node (prev.next = c.next).
  • If exponent does not exist: create a new node and link it between prev and c.
  • Cursor Optimisation: If Q is sorted descending, each successive term has an exponent smaller than or equal to the previous one. Instead of restarting cursor c at the head of R each time, resume searching from where the last term was placed!
1  R = copy of P
2  for each node q in Q:
3    lift q out of its row
4    c = (optimised and cursor set) ? cursor : R.head; prev = node before c
5    while c != NULL and c.exp > q.exp: prev = c; c = c.next
6    if c != NULL and c.exp == q.exp:
7      c.coef = c.coef + q.coef
8      if c.coef == 0: unlink c (prev.next = c.next)
9    else:
10     insert new node (q.coef, q.exp) between prev and c
11   cursor = node where the term landed
12 return R

Complexity: Worst case O(m × n) when cursor restarts. With cursor optimisation on sorted Q, time is O(m + n). Extra space is O(1).

5. Comparison Matrix

Comprehensive algorithmic comparison from PRD Section 10.7:

Approach Time Complexity Extra Space Needs Sorted Input Strengths Weaknesses
Two-pointer O(m + n) O(1) Both P and Q Fastest, simplest traversal Incorrect if either list is unsorted
Nested loop O(m × n) + sort O(n) Neither list Works on completely unordered inputs Slowest; requires final sorting phase
Insertion O(m × n) or O(m + n) O(1) P (and Q for cursor opt) Great for incremental updates, shows pointer re-linking Rescans from head without cursor optimisation
